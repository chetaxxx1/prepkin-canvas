### 4. Tick a row done — extension (6 h)

What the student sees: a circle at the left of every row of ours on the dashboard — the rail's Start-with row and its three Then rows, the card's one line, every planner row, every side-panel row. Not the popup (it has no rows) and not ⌘K results (they are links). On the rail and the card the row leaves at once and the next thing slides in; the rail's foot reads "Done: Problem Set 8 · Undo" for 8 s. On the planner and the side panel the row stays in its day, struck, circle filled, for the rest of the day; the circle toggles. The card says "All done" when something was ticked and nothing is pending; "All handed in" only when something was submitted. Sprout bounces. No `+30` on the page: the coins are the phone's to say.

What the code does:
- Storage: `chrome.storage.local.done = { [taskId]: isoAt }`. The worker is the one writer (`changeDone(fn)` on the `changeRequests` lock pattern); pages send `done` / `undone` messages with the id; `senderMayAsk` gains one line so the side panel (no `sender.tab`) may send them. The worker accepts only an id present in `lastPayload.tasks`; own tasks keep their existing local `submittedAt` tick and never push (R21).
- One pure helper in `day.js`: `withDone(tasks, done)` copies with `doneAt`; `isDone(t) = !!(t.submittedAt || t.doneAt)`. `buckets`, `dueRowsFor`, `nextLineFor`, `weekStats`, the planner's groups and `sidepanel.draw` use `isDone`. `submittedAt` keeps meaning "Canvas verified" (the recap's on-time count, the cheer, R21).
- Readers: `composeData` and `sidepanel.draw` overlay from storage; `storage.onChanged` on `done` re-renders. `send()` in `background.js` bakes `doneAt` into `forBridge.tasks` only, never into `lastResults`. No SQL change: `todo` is opaque jsonb.
- Prune inside `send()`: drop ids no school lists any more, or that now carry `submittedAt`, or that aged past `isWorthShowing`.
- Reconciliation: Canvas later says `submittedAt` → Canvas wins, entry pruned, row locks. Canvas later says `missing` → the student's word stands for the row; `missing` stays on the raw task so the panel's numbers are Canvas's. Undo after the coins were spent → the phone refuses the revoke, keeps the row done; the laptop shows it open; a re-tick pays nothing new (a code comment, not a message to the student).
- Every handler keeps the `e.isTrusted` check.

What proves it:
- `content.test.js`: `buckets` with `doneAt` today → in `doneToday`, not `today`; `voice` says "1 done, 1 to go"; `withDone` never sets `submittedAt`, ignores a submitted task; the prune drops the aged and the submitted; an own-task id is refused by the worker's accept list.
- `test/receipt.test.js` R27: click the first Then row's circle → the row is gone from `#pk-week` within 400 ms, `.pk-card-due` for that course names the next thing, `h.storage().done` holds the id, Undo in the foot restores it, then `syncNow` → `phone.fetchTodo().tasks` carries `doneAt` and `submittedAt: null`. R24 extended: after the real hand-in, `done` no longer holds the id.
- `pages.test.js` "said once per place" unchanged: the circle adds no row and no count.

### 10. Firefox, time-boxed to a day (8 h)

Facts from the manifest and the code (council-checked against MDN/BCD where marked):
- `background.service_worker` is not run by Firefox → add `"scripts": ["background.js"]` beside it (MDN: both keys, each browser takes its own). **`importScripts(...)` at `background.js` L20/24/28 will throw in a Firefox event page** → guard with `typeof importScripts === 'function'` and list `errlog.js`, `canvas.js`, `config.js` in `background.scripts` before `background.js`.
- `side_panel` + the `sidePanel` permission are Chrome-only → `sidebar_action: { default_panel: "sidepanel.html" }` and `browser.sidebarAction.open()` behind the existing `chrome.sidePanel?.open` guard in `popup.js` L454. Firefox's sidebar is per window, not per tab (MDN).
- `use_dynamic_url`, `minimum_chrome_version`: ignored with a warning (Bugzilla/MDN).
- `browser_specific_settings.gecko.id` is required for AMO signing; `strict_min_version` 128 (`optional_host_permissions`).
- `'wasm-unsafe-eval'` in the CSP: accepted.
- **Unverified, test first:** whether Firefox's `chrome.*` alias returns promises with no callback (~40 `await chrome.…` chains depend on it); whether Firefox MV3 treats `host_permissions` (`https://*.supabase.co/*`) as optional at install, which would make the bridge push fail until the student grants it; AMO's data-collection manifest key; AMO source requirement for the minified Sprout bundle.
- Build: one manifest with both background keys if the Chrome floor moves to 121, else `build/firefox/manifest.json` written by a 20-line script. CI: `web-ext lint` on every push; Playwright cannot load Firefox extensions, so the proof is lint plus one geckodriver smoke (install, open the dashboard, `html.pk-on` present, one `fetch_flags` call).
- Stop at the day: if the promise question goes the wrong way it is a port, not packaging; report and park.
